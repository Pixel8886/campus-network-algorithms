# Практическая работа «Сеть между корпусами»

Консольная программа на Java 17+ (проверено на Java 21). Реализует пять алгоритмов на графе из шести корпусов (A–F). Внешних библиотек нет, всё в одном файле.

## Структура проекта

```
campus-network/
├── src/Main.java   # исходный код (данные заданы прямо в коде)
├── output.txt      # вывод программы
└── README.md       # это описание
```

## Запуск

```bash
# Вариант 1: компиляция и запуск
javac -encoding UTF-8 -d out src/Main.java
java -Dfile.encoding=UTF-8 -cp out Main

# Вариант 2: запуск без компиляции (Java 11+)
java src/Main.java
```

Если в консоли Windows вместо `→` и `∞` появляются «кракозябры», выполните `chcp 65001`.

## Алгоритмы (каждый — отдельный метод)

| № | Метод | Задача | Сложность |
|---|-------|--------|-----------|
| 1 | `dijkstra(edges, src)` | кратчайшие задержки из A, восстановление маршрута A → F | O((V+E) log V) |
| 2 | `bellmanFord(edges, src)` | стоимости с отрицательными весами, поиск отрицательного цикла | O(V·E) |
| 3 | `floydWarshall(edges)` | матрица расстояний между всеми парами | O(V³) |
| 4 | `prim(edges, start)` | минимальный остов, старт в A | O(E log V) |
| 5 | `kruskal(edges)` | минимальный остов, сортировка рёбер + DSU | O(E log E) |

Вспомогательные методы: `connectsAll` (проверка связности остова), `pathString` (восстановление пути), `treeDistance` (путь по дереву), `fmt` (вывод ∞).

## Результаты

### Часть 1

**Дейкстра** (задержки): A=0, B=3, C=2, D=8, E=10, F=13.
Маршрут A → F: **A → C → B → D → E → F, 13 мс**.

**Беллман — Форд** (D → E = −2): A=0, B=3, C=2, D=8, E=6, F=9.
Самый дешёвый маршрут A → F: **A → C → B → D → E → F, 9 баллов** (2+1+5−2+3).

После добавления канала **E → B = −4** появляется цикл
B → D → E → B: 5 + (−2) + (−4) = **−1 < 0**.
Он достижим из A (через A → C → B), поэтому, пройдя цикл ещё раз, можно снижать стоимость сколько угодно: A → F **не имеет конечного минимума** (стремится к −∞). Программа обнаруживает это дополнительным N‑м проходом: если после N−1 проходов какая-то релаксация всё ещё улучшает расстояние, отрицательный цикл есть.

**Флойд — Уоршалл** (исходные задержки):

```
      A   B   C   D   E   F
A     0   3   2   8  10  13
B     ∞   0   ∞   5   7  10
C     ∞   1   0   6   8  11
D     ∞   ∞   ∞   0   2   5
E     ∞   ∞   ∞   ∞   0   3
F     ∞   ∞   ∞   ∞   ∞   0
```

Строка A совпадает с результатом Дейкстры — программа проверяет это через `Arrays.equals`. Нули ниже диагонали недостижимы: из-за направленности каналов в A вернуться нельзя.

### Часть 2

| Алгоритм | Выбранные участки | Стоимость |
|----------|-------------------|-----------|
| Прим (старт A) | A—C 3, C—B 2, C—D 4, D—E 2, E—F 3 | **14** тыс. руб. |
| Краскал | B—C 2, D—E 2, A—C 3, E—F 3, C—D 4 | **14** тыс. руб. |

Программа проверяет для каждого результата: все 6 корпусов связаны, участков ровно 5, стоимости алгоритмов равны. Все проверки выдают `true`. Остовы здесь совпали как множества рёбер (порядок выбора разный), потому что веса рёбер, участвующих в выборе, позволяют единственное минимальное дерево.

## Ответ на вопрос: остаётся ли путь A → B кратчайшим?

**Да, остаётся.**

- В дереве Прима путь A → B единственный: **A — C — B = 3 + 2 = 5**.
- В полном графе из части 2 варианты такие: прямой A—B = **6**; A—C—B = 3 + 2 = **5**; A—C—D—B = 3 + 4 + 5 = 12. Минимум — **5**, и это тот же путь.

Прямой участок A—B (6) не вошёл в дерево, но он и не нужен: обходной путь через C дешевле. Расчёт программы это подтверждает (`treeDistance` = 5, Дейкстра на полном графе = 5).

**Важная оговорка.** Это свойство конкретного примера, а не общее правило. Минимальный остов минимизирует суммарную стоимость всех кабелей, но не гарантирует кратчайшие пути между парами вершин. Контрпример: треугольник с рёбрами X—Y = 5, Y—Z = 5, X—Z = 6. Остов — X—Y и Y—Z (10), а путь X → Z по дереву стоит 10, хотя прямой участок стоит 6.
